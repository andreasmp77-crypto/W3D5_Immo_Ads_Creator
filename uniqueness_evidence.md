# Uniqueness Evidence — ImmoAds AI Content Creator

## Overview

This document provides the required uniqueness evidence for the ImmoAds project. It presents a
side-by-side comparison between outputs generated by a generic ChatGPT free-tier prompt and
outputs generated by the ImmoAds pipeline, documents the strategies used to ensure uniqueness,
and demonstrates brand alignment and contextual relevance through concrete examples.

The test property used for all comparisons is:
**Potsdamer Platz 1, 10785 Berlin** — a fully renovated 3-room Altbau apartment, 84.3 m²,
cold rent €1,000, warm rent €1,415, contact: Max Müller, 030 12345678.

---

## 1. The Generic ChatGPT Prompt (Baseline)

The generic prompt used for comparison was entered into ChatGPT Free Tier with the following
instruction:

> *"You are my real estate agent assistant. Please create a PDF file with a description in a
> warm & inviting / professional / premium voice for listing the following property for rent.
> Include information for kindergarten and school and distance to public transport in the
> vicinity of the property."*

The same structured property data block was passed in all three voice variants. No knowledge base,
no PLZ data, no brand guidelines, no secondary research layer — only the raw facts plus a
voice modifier. This is the "AI-Slop" baseline.

## 3. Key Differentiators — What Makes ImmoAds Outputs Unique

### 3.1 Verified Local Data vs. Hallucinated Estimates

The single most important differentiator: **ImmoAds injects verified, real-world data** from
its knowledge base and `location_data.py`, while generic ChatGPT estimates distances and counts
without a data source.

| Data point | Generic ChatGPT | ImmoAds |
|---|---|---|
| Kita count | "several" / "a few" | **11 registered** *(from PLZ JSON)* |
| Kita names | None | FRÖBEL Stepping Stones, KITA Sonnenschein, KiBiLuga |
| School names | None or district-level only | Allegro-Grundschule, Canisius-Kolleg, Internationale Lomonossow-Schule |
| Transport distance | "100–200m", "250m", "2–5 min walk" *(all estimated, inconsistent across runs)* | Live BVG lookup result — honest unavailability flag when data missing |
| Transport lines | "S1, S2, S25, S26, U2" *(stated confidently without verification)* | Not hallucinated — reported as unavailable |

The ChatGPT transport claims are **inconsistent across the three voice runs** (100–200m, 250m,
2–5 min walk) despite identical input — a clear indicator of hallucination rather than retrieval.
ImmoAds uses `location_data.py` with live BVG lookup and a nearest-neighbor fallback, and
**explicitly flags when data is unavailable** rather than inventing figures.

### 3.2 Two Knowledge Bases Drive Contextual Precision

ImmoAds loads both a **primary knowledge base** (brand guidelines, property specs, naming
conventions, tone rules, German real estate terminology) and a **secondary research layer**
(Berlin market positioning, Altbau buyer/renter psychology, PLZ-level neighborhood profiles).
Generic ChatGPT has access to none of this — it generates from statistical word patterns alone.

This is why ImmoAds outputs correctly use:
- **Nebenkosten** (not just "additional costs")
- **Altbau** as a distinct property typology signal, not just "old building"
- PLZ as a structural identifier, not just a postcode
- Structured `Location facts:` block as a reusable data section for the PDF template

### 3.3 Voice Templates Are Reusable and Consistent

ImmoAds uses `prompt_templates.py` to separate owner data, knowledge-base context, and
location facts into distinct prompt blocks. This means:

- The same property produces **reliably different but brand-consistent outputs** across voice variants
- Outputs do not drift mid-text from one register to another (a common ChatGPT failure mode)
- The voice modifier is applied at the template level, not as a throw-away instruction

### 3.4 Human-in-the-Loop Review Step

The pipeline includes an explicit **Human Review / Edit** stage (M5) before final output.
Generic ChatGPT produces a single output with no structured review gate. ImmoAds treats the
LLM draft as a starting point — the landlord or agent reviews, edits, and approves before
the PDF is rendered. This reduces the risk of publishing hallucinated claims (e.g., wrong
transport distances) and keeps the human accountable for the final listing.

### 3.5 Structured PDF Output vs. Plain Text

ImmoAds renders output via `pdf_export.py` using a templated PDF layout with:
- Labelled sections matching German rental listing conventions
- Separated `Location facts:` block for easy verification
- Consistent contact block formatting
- Clear price breakdown (Kaltmiete / Nebenkosten / Warmmiete)

Generic ChatGPT produces plain text that varies in structure across runs.

## 4. Strategies Used to Ensure Uniqueness

### Strategy 1 — Contextual Knowledge Injection (Primary KB)
Brand guidelines, property type taxonomy, and German real estate terminology are loaded from
`knowledge_base/primary/` markdown files and injected into every prompt. This grounds the output
in domain-specific language that generic models do not consistently apply.

### Strategy 2 — Live Location Data Retrieval (Secondary KB + location_data.py)
Real PLZ-level Kita counts, school names, and BVG transport data are fetched at runtime by
`location_data.py`. The nearest-neighbor fallback ensures the system never silently fails —
it either returns real data or reports the gap honestly. This is the sharpest single
differentiator from generic ChatGPT, which hallucinates these details.

### Strategy 3 — Separated Prompt Architecture (prompt_templates.py)
Owner facts, KB context, and location data are injected as distinct blocks in the prompt
rather than as one merged string. This prevents the model from blending unverified
associations and forces it to treat each data source as authoritative in its own domain.

### Strategy 4 — Voice-Locked Templates
Each of the three output tones (Warm & Inviting, Professional, Premium) is implemented as a
dedicated template with fixed structural requirements and tone anchors. The voice does not
drift because the template constrains it — not because the model happens to stay on-register.

### Strategy 5 — Human-in-the-Loop Gate (M5)
An explicit review stage is built into the pipeline before PDF export. The human reviewer is
the last line of defence against hallucinated facts reaching the published listing.

### Strategy 6 — Honest Fallback Reporting
When live data is unavailable (e.g., BVG transport for PLZ 10785), ImmoAds reports the gap
explicitly in the output rather than fabricating a plausible-sounding estimate. This is a
deliberate design choice that distinguishes the system from generic AI generation.

## 5. Brand Alignment and Contextual Relevance Examples

### Example A — Kita and School Section
Generic ChatGPT (all three voices) produces distance estimates with no institution names:

> *"Several kindergartens within approximately 500–1,000 metres"*

ImmoAds produces a named, counted, verifiable section:

> *"11 registered Kitas, including FRÖBEL Kindergarten Stepping Stones, KITA Sonnenschein,
> KiBiLuga. Schools: Allegro-Grundschule, Canisius-Kolleg, Internationale
> Lomonossow-Schule Berlin (Gemeinschaftsschule)."*

A landlord using the ImmoAds output can **verify and stand behind every claim**. A landlord
using the ChatGPT output cannot.

### Example B — Transport Honesty
Across three ChatGPT runs, transport distance to Potsdamer Platz station was reported as:
- "100–200 metres" (Warm run)
- "250 metres, 3–4 minutes" (Professional run)
- "2–5 minutes' walk" (Premium run)

These are three different answers from the same input. ImmoAds reports:
> *"Public transport: data unavailable for this PLZ."*

Factually conservative, but honest and legally defensible for a published rental listing.

### Example C — German Market Terminology
ImmoAds consistently uses `Nebenkosten`, `Kaltmiete`, `Warmmiete`, `Altbau`, and `PLZ` —
the standard terms used in German property portals (ImmobilienScout24, Immowelt). Generic
ChatGPT alternates between English and German terms unpredictably across runs.
